# SSH Remote — план доработок P0–P1

Состояние на 2026-10-26. Область: только P0 (риск) и P1 (отдача). P2 (латентность,
`/ssh forget`, перенос паролей в хранилище хоста, `scp -r`) сюда не входит.

> **Все пункты P0-1 … P1-8 реализованы.** План оставлен как запись решений; что
> именно сделано и где это лежит — в разделе «Что сделано» в конце файла.
> Счётчики тестов выросли: `test-args.mjs` 48 → 65, `test-host.mjs` 57 → 72 (плюс две проверки
> атомарной замены файла).

**Контекст, из которого выбраны приоритеты**

- Реестр: два сервера, вход `root`, аутентификация ключом (`192.0.2.10`,
  `203.0.113.7`).
- Удалённые команды выполняются с правами ключа; файловая песочница DSH их не
  ограничивает (`index.js:15`).
- Хост: DSH `0.2.1-rc.3`; плагин подключён как `link:`, правки подхватываются
  после перезапуска Harness.
- Текущая база: 48 проверок `test-args.mjs` + 57 `test-host.mjs`, обе зелёные.
  Ни одна задача ниже не должна добавлять зависимостей.

**Легенда**

- **P0** — безопасность: закрывает то, что при `root` может стать необратимым.
- **P1** — функциональность/надёжность с быстрой отдачей.

## P0-1. Гейт на разрушительные команды в `ssh_run` — сделано

**Проблема.** `ssh_run` передаёт в `ssh` любую строку без проверки: `rm -rf /`,
`dd of=/dev/sda`, `mkfs.ext4`, `shutdown` уходят молча. Единственная защита —
белый список серверов и `lock`, но они отвечают на вопрос «куда», а не «что».

**Что сделать.**

1. В `args.js` — чистая функция `classifyCommand(command)` →
   `{ tier: 'block' | 'ask' | 'allow', reason }`.
   - `block` (однозначно катастрофичное): `rm -rf /`, `rm -rf /*`,
     `rm -rf ~`, `mkfs.*`, `dd of=/dev/`, `:(){`, `shutdown|reboot|halt|poweroff`,
     `chmod -R 777 /`, `> /dev/sd*`.
   - `ask` (необратимо, но законно): `rm -rf`, `docker system prune`,
     `docker volume rm`, `apt purge`, `kill -9 1`, `DROP DATABASE`, `TRUNCATE`.
   - `allow` — всё остальное.
2. `guard` (`index.js:899`) — только `block`: guard синхронный, спросить не может,
   поэтому возвращает готовую строку отказа с объяснением.
3. `ask` — в `ssh_run.execute` до `runCommand`, через существующий `confirm()`
   (`index.js:557`): показать команду, сервер и путь, требовать явного выбора.
   Без answerer'а — отказ (уже fail-closed по факту отсутствия `userQuestions`).
4. Конфиг: `commandPolicy: 'standard' | 'off'` (по умолчанию `standard`).
   `off` не отключает `block` — только `ask`, и пишет warn в лог.

**Ограничение, которое нужно зафиксировать в README.** Сопоставление по
шаблонам — лежачий полицейский, а не граница: `rm -rf $(echo /)` пройдёт.
Настоящая граница — отдельный пользователь на сервере без `sudo`, и это
рекомендация по эксплуатации, а не код.

**Тесты (`test-args.mjs`).** Таблица: строка → ожидаемый tier (не менее 25
случаев, включая близкие к безопасным: `rm -rf ./build`, `echo "rm -rf /"`,
`docker prune` в комментарии). В `test-host.mjs` — `ask` без answerer'а
отклоняется, `block` отклоняется guard'ом до запуска процесса.

**Оценка.** ~80 строк кода, ~40 строк тестов.

**Открытый вопрос (решён при реализации).** В `ask` попал весь перечисленный
класс (`rm -rf` по необратимому пути, `docker system prune`/`volume rm`, `apt
purge`, `kill -9 1`, `DROP DATABASE`/`TRUNCATE`), **кроме** обычного удаления
проектного каталога: `rm -rf` спрашивает, только если цель — абсолютный путь,
`.`/`..` или маска, поэтому `rm -rf ./build` и `rm -rf node_modules` проходят
без вопроса. Причина: подтверждение на каждой уборке `build/` приучило бы
нажимать «Run it» не читая, и настоящее предупреждение перестало бы работать.

**Приёмка.** `rm -rf /` не запускает процесс; `rm -rf ./build` проходит без
вопроса в `standard`; отказ содержит команду и причину.

## P0-2. Вырезание секретов из вывода перед отправкой модели — сделано

**Проблема.** `formatRunResult` (`args.js:325`) отдаёт stdout/stderr как есть.
`cat ~/.ssh/id_rsa`, `env`, `docker inspect`, `wp-config.php`, `mysql -p…`
попадают в переписку — то есть уходят провайдеру модели.

**Что сделать.** В `args.js` — `redact(text)` → `{ text, count }`; применить в
`formatRunResult` к stdout и stderr до сборки отчёта.

Шаблоны только высоконадёжные (иначе порежется нормальный вывод):

- блоки `-----BEGIN … PRIVATE KEY-----` … `-----END … PRIVATE KEY-----`;
- AWS access key: `AKIA[0-9A-Z]{16}`;
- `sk-[A-Za-z0-9]{20,}`;
- JWT: `eyJ[A-Za-z0-9_-]{10,}\.[A-Za-z0-9_-]{10,}\.[A-Za-z0-9_-]{10,}`;
- `(password|passwd|pwd|secret|token|api[_-]?key)\s*[=:]\s*\S+`;
- `Authorization: Bearer \S+`;
- URL с учётными данными: `[a-z]+://[^/\s:]+:[^/\s@]+@`.

Замена — `«redacted:<тип>»`; в конце отчёта строка `… вырезано N секретов`.
Ничего не писать в консольный лог в открытом виде — редактировать до логирования.

**Тесты (`test-args.mjs`).** Каждый шаблон — положительный случай; отрицательные:
`password=` в обычном тексте без значения, `rm -rf /` в кавычках, base64-хвост,
обычный URL без кредов. Проверить, что `count` совпадает с числом замен.

**Оценка.** ~60 строк, ~30 строк тестов.

**Приёмка.** `ssh_run` с `cat` приватного ключа возвращает отчёт без тела ключа.

## P0-3. ACL на хранилище паролей в Windows — сделано

**Проблема.** `restrictPermissions` (`secrets.js:51`) вызывает `chmod 600`,
который на Windows — no-op. `ssh-remote-secrets.json` наследует ACL каталога,
то есть читается любым процессом пользователя.

**Что сделать.** После атомарной записи (после `rename`, `secrets.js:112`) на
`win32` выполнить

```
icacls "<path>" /inheritance:r /grant:r "<DOMAIN\User>":F
```

через `subprocess.spawn` с `stdio: 'ignore'`, коротким таймаутом; ошибку — в
`logger.warn`, не в исключение (запись пароля не должна падать из-за ACL).
Имя пользователя брать из `os.userInfo().username` + `USERDOMAIN`, не из
окружения целиком. Применить и к каталогу askpass (`secrets.js:214`) —
он живёт секунды, но лежит с паролем внутри.

**Тесты.** Юнит: функция строит корректный argv (без shell), на `linux`/`darwin`
не вызывается вовсе. Пропускать реальный `icacls` в CI нельзя — только argv.

**Оценка.** ~40 строк, ~15 строк тестов.

**Приёмка.** После `/ssh pass` у файла нет унаследованных ACE; README-формулировка
про «читает любой процесс пользователя» заменена на «ваш аккаунт и администраторы».

## P1-4. Навигация по удалённой ФС: `ssh_read`, `ssh_ls`, `ssh_grep`, `ssh_glob` — сделано

**Проблема.** Исследование удалённого дерева сейчас = сочинённый `find … | head`
на каждый шаг, с риском упереться в `maxOutputChars`. Именно эти четыре
инструмента есть у `dsh-remote-ssh` (13 штук), и именно их не хватает.

**Что сделать.** Регистрации рядом с `ssh_run`, все — поверх `runCommand`
(без SFTP, без новых зависимостей):

- `ssh_read`: `path`, `offset` (строка или байт), `limit` — через `sed -n` или
  `tail -c +N | head -c M`; помечать, что прочитано не всё;
- `ssh_ls`: `path`, `long?` — `ls -la` с обрезкой;
- `ssh_grep`: `pattern`, `path`, `glob?`, `maxMatches?` — `grep -rn --binary-files=without-match`;
- `ssh_glob`: `pattern`, `path?`, `maxResults?` — `find -name`/`-path` с потолком.

Все аргументы — через `shellQuote` (`args.js:200`), никакой конкатенации без
кавычек. Каждый инструмент — `presentCall` с `card: 'terminal'`, как у `ssh_run`.

**Тесты.** `test-host.mjs` на поддельном subprocess: argv корректен для путей с
пробелами, кавычками, `$(…)`, юникодом; `offset`/`limit` не теряют и не
дублируют строки; превышение `maxMatches` помечается как усечение.

**Оценка.** ~150 строк, ~40 строк тестов.

**Приёмка.** Агент читает большой лог по частям и находит файл по маске, не
сочиняя `find` вручную.

## P1-5. Обрезка вывода: голова + хвост — сделано

**Проблема.** `truncate()` (`args.js:307`) оставляет только начало. В длинном
логе сборки причина падения — в конце, и модель её не видит.

**Что сделать.** Оставить 60% бюджета от головы и 40% от хвоста, между ними
строка `… пропущено N символов (из M) …`. Для stderr — то же. Сохранить
нынешний контракт `{ text, truncated, note }`, чтобы не править вызовы.

**Тесты.** Границы: ровно `maxChars`, `maxChars + 1`, пустая строка, текст
короче бюджета; проверка, что сумма частей + маркер не превышает бюджет
существенно (маркер — за счёт запаса).

**Оценка.** ~25 строк, ~15 строк тестов.

**Приёмка.** Лог на 500 КБ даёт видимый хвост, а не только первые 60 КБ.

## P1-6. Аудит-лог действий — сделано

**Проблема.** При `root` на двух машинах нет ответа на вопрос «что агент делал
вчера»: вывод живёт в сессии, а сессии удаляются.

**Что сделать.** `audit.js`, запись JSONL в `$DSH_HOME/ssh-remote-audit.jsonl`:
`ts`, `server`, `host`, `tool`, `command` (первые 200 символов **после**
`redact`), `exitCode`, `durationMs`, `timedOut`, `passwordAuth`. Вызов — из
`runProcess` (`index.js:389`), после получения исхода, не блокируя результат:
ошибку записи только логировать. Ротация — по размеру (например 10 МБ → `.1`),
без внешних зависимостей.

**Тесты.** `test-host.mjs`: строка пишется при успехе и при ошибке; секреты в
`command` вырезаны; недоступный путь логируется, но не ломает вызов.

**Оценка.** ~50 строк, ~20 строк тестов.

**Приёмка.** После серии команд файл читается `jq`-совместимо, по строке на вызов.

## P1-7. Уникальные имена временных файлов — сделано

**Проблема.** `registry.js:214` и `secrets.js:106` пишут в `${path}.tmp` —
фиксированное имя. Desktop и web-профиль одновременно (или второй экземпляр DSH)
затирают друг друга: один `rename` уносит чужую запись.

**Что сделать.** `${path}.${process.pid}.${randomUUID()}.tmp` в обоих местах;
`rename` остаётся атомарным. Заодно `fsync` файла перед `rename`, если хочется
переживать отключение питания (необязательно, отметить в комментарии).

**Тесты (`test-args.mjs`).** Два параллельных `writeRegistry` с разными
документами: в файле ровно один из них целиком, `.tmp` не остаётся.

**Оценка.** ~10 строк, ~10 строк тестов.

**Приёмка.** Параллельная запись не оставляет мусора и не теряет данные.

## P1-8. `tty` и `detached` в `ssh_run` — сделано

**Проблема.** Интерактивные утилиты и `sudo` без `NOPASSWD` не работают
(`-T` жёстко зашит, `args.js:155`); долгие задачи README предлагает оборачивать
в `nohup` руками.

**Что сделать.**

- `tty: true` → `-tt` вместо `-T`; предупредить в описании параметра, что
  вывод содержит управляющие последовательности;
- `detached: true` → обернуть в `nohup <cmd> > <log> 2>&1 & echo $!`,
  вернуть pid и путь лога; путь по умолчанию — `/tmp/ssh-remote-<id>.log`.

**Отдельно про таймаут.** `handle.terminate()` (`index.js:415`) убивает
локальный `ssh`; удалённый процесс может выжить — с `apt` это оставит занятый
`dpkg`-lock. Дописать это в текст ошибки таймаута и рекомендовать `detached`
для долгих операций.

**Тесты.** `test-args.mjs`: `tty` меняет `-T`/`-tt` и не дублирует флаг;
`detached` даёт корректно закавыченный argv и парсит pid из вывода.

**Оценка.** ~40 строк, ~20 строк тестов.

**Приёмка.** `ssh_run` с `tty` проходит на `top -b -n1`; `detached` возвращает
живой pid и растущий лог.
